

# Phase 1

## file stucture
app - исходный код основного сервиса
doc - документация
cli - исходный код прилоения которое помещается в контейнер с сервером и служит для тестирования и обслуживания сервиса. втсроенные интеграционные тесты в cli станут достаточным критерием готовности сервиса
it.sh - запуск контейнера в интерактивном окружении в отладочном режиме
make_app.sh - собрать контейнер приложения
make_base.sh - собрать сборочный контейнер с библиотеками и инструментами компиляции
make_test - собрать и запустить контейнер юнит тестов

## структура основого сервиса
blob_storage.h/cpp - контроллер объектного k/v хранилища 
meta_storage.h/cpp - контроллер хранилища метаинформации
types.h/cpp  - временное хранилище типов данных
engine.h/cpp - реализация основной логики хранилища
http_endpoint.h/cpp - http api сервис

## blob_storage
класс управления key value таблицей orb_blob
таблица состоит из двух колонок. 
key - varchar(128) - pk, unique
value - jsonb - not null
класс инициализируется настройкой подключения к базе через стандартную структуру dbconfig
использует soci для создания и работой с таблицей. 
пример можно найти в services\signaling_cpp\app\message_storage.cpp

сервис имеет следующий интерфейс для работы с данными

bool contains(id) - есть ли запись в таблице
bool store(id, const boost::json::object& data) - обновить запись в таблице. если записи нет то создать. возвращает true в случае успеха
optional<boost::json::object> load(id) - возвращает объект если он есть
size_t count() количество записей в таблице
bool ok() - признак того что подключение к базе установлено и работает

пример можно найти в services\signaling_cpp\app\message_storage.cpp
сервис имеет следующий интерфейс для работы с данными

bool store(id, const InternalMetaObject& data) - обновить запись в таблице. если записи нет то создать. возвращает true в случае успеха
optional<InternalMetaObject> load(id) - возвращает объект если он есть
size_t count() количество записей в таблице
