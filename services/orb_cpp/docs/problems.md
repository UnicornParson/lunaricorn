# Известные проблемы и ограничения

## Phase 1

### Ограничения

- **Отсутствие юнит-тестов**: инфраструктура `make_test` не настроена. Качество кода проверяется только через сборку и запуск в интерактивном контейнере.
- **Нет кэширования**: каждый запрос к BlobStorage/MetaStorage выполняет прямой SQL-запрос к PostgreSQL. При высокой нагрузке потребуется ввести кэширующий слой.
- **Одиночный поток io_context**: HttpEndpoint использует `asio::io_context` с 1 потоком. Для production-нагрузки потребуется увеличить количество потоков или использовать thread pool.

### Технический долг

- Библиотека Poco (используется в `main.cpp` для констант и leader API) частично дублируется Boost.Asio/Beast. В перспективе возможно унифицировать сетевой стек.
- `LeaderConnector` продолжает использовать Poco. Если leader API будет переписан на Boost, его можно будет удалить из зависимостей.
- **Схема БД без миграций**: таблицы `orb_meta` и `orb_blob` создаются через `CREATE TABLE IF NOT EXISTS` при старте сервиса. При изменении схемы (добавление/удаление колонок) нет механизма миграций — требуется ручное ALTER TABLE или ресет БД. В ходе разработки была обнаружена проблема отсутствия колонок `parent`, `prev`, `next` в `orb_meta` (создана предыдущей версией кода), исправлена ручным ALTER TABLE.

## Phase 2

### Ограничения

- **Нет интеграции с кластером**: orb_cpp не имеет поддержки `CLUSTER_LEADER_URL` и `MAINTENANCE_*` переменных окружения. Сервис не знает о существовании leader-ноды и maintenance-сервиса.
- **Нет в docker-compose.yaml**: сервис orb_cpp не добавлен в `services/docker-compose.yaml`. Для запуска требуется ручная конфигурация Docker-контейнера.
- **Тесты через сырой HTTP**: `cli/http_test.h/cpp` используют Poco::Net HTTP вместо OrbClient/OrbObject. Тесты через клиентскую библиотеку не реализованы.
- **Boost.UUID не в CMake**: в `lunaricorn/cpp/CMakeLists.txt` Boost.UUID не указан в `find_package(Boost COMPONENTS ...)`. Может привести к ошибкам линковки на новых сборках.
- **Нет скриптов запуска**: `orb_up.sh`, `build.sh`, `up.sh` не обновлены для работы с orb_cpp.

### Технический долг

- **Порт 8081 конфликтует с signaling_cpp**: оба сервиса слушают 8081. При одновременном запуске на одном хосте нужен внешний reverse proxy или перенос одного из сервисов на другой порт.
- **Синхронные HTTP-запросы в OrbClient**: `do_request()` блокирует вызывающий поток. Для production-использования следует переделать на async-запросы.
- **OrbObject кэширует всё**: `OrbObject` кэширует все поля мета-объекта и не имеет инвалидации кеша. При изменении объекта извне потребуется `refresh()` или TTL.
