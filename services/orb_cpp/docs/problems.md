# Известные проблемы и ограничения

## Phase 1

### Ограничения

- **Отсутствие юнит-тестов**: инфраструктура `make_test` не настроена. Качество кода проверяется только через сборку и запуск в интерактивном контейнере.
- **Нет кэширования**: каждый запрос к BlobStorage/MetaStorage выполняет прямой SQL-запрос к PostgreSQL. При высокой нагрузке потребуется ввести кэширующий слой.
- **Одиночный поток io_context**: HttpEndpoint использует `asio::io_context` с 1 потоком. Для production-нагрузки потребуется увеличить количество потоков или использовать thread pool.

### Технический долг

- Библиотека Poco (используется в `main.cpp` для констант и leader API) частично дублируется Boost.Asio/Beast. В перспективе возможно унифицировать сетевой стек.
- `LeaderConnector` продолжает использовать Poco. Если leader API будет переписан на Boost, его можно будет удалить из зависимостей.
- **Схема БД без миграций**: таблицы `orb_meta` и `orb_blob` создаются через `CREATE TABLE IF NOT EXISTS` при старте сервиса. При изменении схемы (добавление/удаление колонок) нет механизма миграций — требуется ручное ALTER TABLE или ресет БД. В ходе разработки была обнаружена проблема отсутствия колонок `parent`, `prev`, `next` в `orb_meta` (создана предыдущей версией кода), исправлена ручным ALTER TABLE.
