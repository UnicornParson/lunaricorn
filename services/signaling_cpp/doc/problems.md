# Problems: Известные проблемы и технический долг

## Критические

### P1: HTTP_Endpoint не реализован
- **Статус:** ❌ Не начат
- **Файл:** `app/http_endpoint.cpp` — все методы возвращают false/пусто
- **Влияние:** Нет REST API для интеграции с HTTP-клиентами
- **Рекомендация:** Приоритет High — реализовать на базе Poco HTTP Server

### P2: Reconnect логика отсутствует
- **Статус:** ❌ Не реализовано
- **Влияние:** При разрыве соединения клиент должен переподключиться вручную
- **Рекомендация:** Добавить exponential backoff reconnect в RE_Client или отдельном классе

### P3: Подписки не работают с SignalingEngine
- **Статус:** ⚠️ Частично
- **Файл:** `raw_endpoint.cpp::processSubscription()`
- **Проблема:** Отправляет ACK, но не вызывает `engine->subscribe()`
- **Влияние:** Клиенты не получают pushed события после подписки
- **Рекомендация:** Связать `processSubscription` с `engine->subscribe()`

## Средние

### M1: QueryRequest не использует SignalingEngine
- **Статус:** ⚠️ Заглушка
- **Файл:** `raw_endpoint.cpp::processQueryRequest()`
- **Проблема:** Отправляет ACK, но не выполняет поиск через engine
- **Рекомендация:** Связать с `engine->findEvents()`

### M2: processPushRequest не интегрирован с engine
- **Статус:** ⚠️ Заглушка
- **Файл:** `raw_endpoint.cpp::processPushRequest()`
- **Проблема:** Отправляет ACK, но не создаёт событие через engine
- **Рекомендация:** Связать с `engine->createEvent()`

### M3: Нет обработки типов подписки
- **Статус:** ⚠️ Частично
- **Файл:** `raw_endpoint.cpp::processSubscription()`
- **Проблема:** Payload подписки парсится, но фильтры не извлекаются
- **Рекомендация:** Парсить JSON payload для извлечения filter_types, filter_sources и т.д.
