# Задача для Cline: Исправление критических и высокоприоритетных проблем в `jita_loader.py`

---

## Контекст

Файл `jita_loader.py` — скрипт загрузки рыночных ордеров из ESI API (EVE Online) в PostgreSQL. При запуске скрипт падает или работает некорректно из-за ряда критических и высокоприоритетных багов. Лог запуска (`#577.txt`) показывает, что формируется один SQL-INSERT на 10 812 записей, что приводит к таймаутам и падению.

---

## Задача 1 (КРИТИЧЕСКАЯ): Разбить массовый INSERT предметов на батчи

### Проблема
В функции `update_types_reference` выполняется один `pg_insert(EveType).values(list(types.values()))` для всех 10 812 записей одновременно. Это создаёт ~64 872 параметра в одном SQL-запросе, что превышает лимиты и вызывает таймаут.

### Что сделать
Найти в функции `update_types_reference` блок:

```python
if types:
    stmt = pg_insert(EveType).values(list(types.values()))
    stmt = stmt.on_conflict_do_update(
        index_elements=['type_id'],
        set_={
            'name': stmt.excluded.name,
            'group_id': stmt.excluded.group_id,
            'market_group_id': stmt.excluded.market_group_id,
            'description': stmt.excluded.description,
            'published': stmt.excluded.published
        }
    )
    db.execute(stmt)
    db.commit()
```

Заменить на пакетную вставку по 500 записей:

```python
BATCH_SIZE = 500
if types:
    items = list(types.values())
    for i in range(0, len(items), BATCH_SIZE):
        batch = items[i:i + BATCH_SIZE]
        stmt = pg_insert(EveType).values(batch)
        stmt = stmt.on_conflict_do_update(
            index_elements=['type_id'],
            set_={
                'name': stmt.excluded.name,
                'group_id': stmt.excluded.group_id,
                'market_group_id': stmt.excluded.market_group_id,
                'description': stmt.excluded.description,
                'published': stmt.excluded.published
            }
        )
        db.execute(stmt)
        db.commit()
```

Аналогично проверить функции `update_region_reference` для `constellations_data` и `systems_data` — если там тоже массовый UPSERT без батчинга, добавить аналогичный механизм.

### Критерий приёмки
- В логе больше не появляется SQL-запрос с параметрами выше `%(type_id_m500)s`.
- Вставка завершается без таймаутов.

## Задача 2 (КРИТИЧЕСКАЯ): Исправить синтаксические ошибки

### Проблема
В коде имеются синтаксические ошибки, из-за которых скрипт не может быть корректно интерпретирован.

### Что исправить

**2.1. Слипание `return True` и следующего `def`:**

Найти все вхождения вида:
```python
return Truedef get_robust_session() -> requests.Session:
```
```python
return None, Nonedef get_all_market_orders(...):
```
```python
return Truedef update_types_reference(...):
```
```python
return Truedef update_region_reference(...):
```

Заменить на:
```python
return True


def get_robust_session() -> requests.Session:
```
(аналогично для остальных — вставить два перевода строки между `return` и `def`)

**2.2. Пробел в f-строке:**

Найти:
```python
print(f "❌ Критическая ошибка при загрузке региона {reg_name}: {e} ")
```
Заменить на:
```python
print(f"❌ Критическая ошибка при загрузке региона {reg_name}: {e}")
```

**2.3. Неправильная проверка точки входа:**

Найти:
```python
if name == " main ":
```
Заменить на:
```python
if __name__ == "__main__":
```

**2.4. Пробелы в тройных кавычках:**

Найти:
```python
" " "
```
Заменить на:
```python
"""
```

### Критерий приёмки
- `python -m py_compile jita_loader.py` выполняется без ошибок.

## Задача 3 (ВЫСОКИЙ): Исправить переопределение словаря регионов

### Проблема
В блоке `if __name__ == "__main__":` словарь `regions` определяется дважды:

```python
regions = {
    "jita ": 10000002,
    "amarr ": 10000043,
    "hek ": 10000042,
    "dodixie ": 10000032,
    "rens ": 10000030
}
regions = {
    "rens ": 10000030
}
```

Второе присваивание перезаписывает первое, поэтому загружается только Rens.

### Что сделать
- Удалить второе переопределение `regions = {"rens ": 10000030}`.
- Исправить ключи — убрать лишние пробелы:

```python
regions = {
    "jita": 10000002,
    "amarr": 10000043,
    "hek": 10000042,
    "dodixie": 10000032,
    "rens": 10000030
}
```

### Критерий приёмки
- В логе видно последовательную загрузку всех 5 регионов.
- В выводе `print` имена регионов без лишних пробелов.

## Задача 4 (ВЫСОКИЙ): Добавить защиту от потери данных при ошибке страницы

### Проблема
В функции `get_all_market_orders` при неудачной загрузке страницы:
```python
if raw_data is None:
    print(f"\n⚠️ Не удалось получить страницу {page} после всех попыток. Пропускаем её.")
    continue
```
Данные страницы теряются безвозвратно.

### Что сделать
Заменить на логику с повторной попыткой и предупреждением:

```python
if raw_data is None:
    print(f"\n⚠️ Не удалось получить страницу {page}. Повторная попытка через 5 секунд...")
    time.sleep(5)
    raw_data, _ = get_market_orders_raw(session, region_id, page, order_type)
    if raw_data is None:
        print(f"❌ Страница {page} недоступна после повторной попытки. Пропускаем.")
        continue
```

### Критерий приёмки
- При ошибке страницы скрипт делает минимум одну повторную попытку.
- В логе видно сообщение о повторной попытке.

## Задача 5 (ВЫСОКИЙ): Исправить дублирование и обрыв строки в `update_types_reference`

### Проблема
В коде есть оборванная строка:
```python
print(f" ✅ Категорий: {len(categories)}, групп: {len(groups)},db.execute(stmt)
db.commit()
print(f" ✅ Категорий: {len(categories)}, групп: {len(groups)}, типов: {len(types)}")
```

Это дублирование и синтаксическая ошибка.

### Что сделать
Оставить только одну корректную строку:
```python
print(f"✅ Категорий: {len(categories)}, групп: {len(groups)}, типов: {len(types)}")
```

Удалить дублирующий `db.execute(stmt)` и `db.commit()` если они уже выполнены в блоке выше.

## Задача 6 (ВЫСОКИЙ): Исправить пробелы в `session.mount`

### Проблема
```python
session.mount("http:// ", adapter)
session.mount("https:// ", adapter)
```

Пробел в конце префикса делает монтаж неэффективным.

### Что сделать
```python
session.mount("http://", adapter)
session.mount("https://", adapter)
```

Аналогично в `Retry`:
```python
allowed_methods=["HEAD", "GET", "OPTIONS"]
```
