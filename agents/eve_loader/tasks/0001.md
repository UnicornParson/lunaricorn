

# Задача для Cline: полностью убрать сохранение `description` из справочников

## Цель

Перестать читать и сохранять любые текстовые описания из ESI в справочные таблицы.

Нужно убрать `description` из всех полезных нагрузок, которые попадают в `INSERT` / `UPSERT`.

При этом:

- таблицы в БД **не меняем**;
- колонки `description` в SQLAlchemy-моделях **не удаляем**;
- список регионов **не меняем**;
- логика загрузки ордеров не меняется;
- нужно только убрать работу с описаниями.

---

## Ограничения

### Нельзя делать

```python
ALTER TABLE ...
```

Нельзя удалять колонки из моделей:

```python
description = Column(String(500), nullable=True)
```

```python
description = Column(String(2000), nullable=True)
```

Их оставляем как есть, чтобы не менять определение схемы.

### Нельзя трогать список регионов

Текущий тестовый список регионов оставляем как есть.

---

# 1. Изменить `update_region_reference`

Найти место, где формируется данные для региона.

Скорее всего сейчас есть что-то вроде:

```python
region_data = {
    'region_id': region_id,
    'name': region_json['name'],
    'description': region_json.get('description'),
}
```

или похожая конструкция.

Нужно заменить на вариант без текста описания.

## Рекомендуемый вариант

```python
region_data = {
    'region_id': region_id,
    'name': region_json['name'],
    'description': None,
}
```

Это безопасно: колонка остаётся, но в неё пишется `NULL`, а не длинный текст из ESI.

Если где-то есть отдельная переменная:

```python
description = region_json.get('description')
```

её нужно удалить или не использовать.

---

## Изменить UPSERT региона

Найти блок вида:

```python
stmt = pg_insert(EveRegion).values(region_data)
stmt = stmt.on_conflict_do_update(
    index_elements=['region_id'],
    set_={
        'name': stmt.excluded.name,
        'description': stmt.excluded.description
    }
)
```

Заменить на:

```python
stmt = pg_insert(EveRegion).values(region_data)
stmt = stmt.on_conflict_do_update(
    index_elements=['region_id'],
    set_={
        'name': stmt.excluded.name,
        'description': None
    }
)
```

Если `values()` вызывается со списком:

```python
stmt = pg_insert(EveRegion).values([region_data])
```

то оставляем список, просто меняем содержимое `region_data`.

---

## Итоговый смысл

Для региона сохраняем только:

```python
region_id
name
```

`description` больше не читаем из ESI как текст.

---

# 2. Изменить `update_types_reference`

Найти формирование словаря `types`.

Сейчас там есть что-то вроде:

```python
types[type_id] = {
    'type_id': type_json['type_id'],
    'name': type_json['name'],
    'group_id': type_json['group_id'],
    'market_group_id': type_json.get('market_group_id'),
    'description': type_json.get('description'),
    'published': type_json.get('published', True)
}
```

Нужно заменить на:

```python
types[type_id] = {
    'type_id': type_json['type_id'],
    'name': type_json['name'],
    'group_id': type_json['group_id'],
    'market_group_id': type_json.get('market_group_id'),
    'published': type_json.get('published', True),
    'description': None
}
```

То есть полностью убрать:

```python
'description': type_json.get('description')
```

---

## Изменить UPSERT типов

Найти блок:

```python
stmt = pg_insert(EveType).values(batch)
stmt = stmt.on_conflict_do_update(
    index_elements=['type_id'],
    set_={
        'name': stmt.excluded.name,
        'group_id': stmt.excluded.group_id,
        'market_group_id': stmt.excluded.market_group_id,
        'description': stmt.excluded.description,
        'published': stmt.excluded.published
    }
)
```

Заменить на:

```python
stmt = pg_insert(EveType).values(batch)
stmt = stmt.on_conflict_do_update(
    index_elements=['type_id'],
    set_={
        'name': stmt.excluded.name,
        'group_id': stmt.excluded.group_id,
        'market_group_id': stmt.excluded.market_group_id,
        'published': stmt.excluded.published,
        'description': None
    }
)
```

Если где-то ещё остался массовый UPSERT без батчей:

```python
stmt = pg_insert(EveType).values(list(types.values()))
```

то `set_` всё равно нужно исправить так же.

Проверить таблицы:

```python

```

Если там вдруг есть `description`, его тоже нужно убрать из словарей и `set_`.

```python
EveRegion.description
EveType.description
```

# 4. Запрещённые конструкции после правки

После изменений в коде не должно быть:

```python
region_json.get('description')
```

```python
type_json.get('description')
```

```python
stmt.excluded.description
```

```python
'description': type_json[...]
```

```python
'description': region_json[...]
```

Допустимо только:

```python
'description': None
```

или полное отсутствие ключа `description` в словаре.

Но рекомендую оставить именно:

```python
'description': None
```

чтобы старые описания не оставались в уже существующих строках.

---

# 5. Что должно получиться в логах

После правки в SQL-логах больше не должно быть длинных параметров вида:

```sql
%(description_m0)s
%(description_m1)s
...
%(description_m10000)s
```

Должно быть либо отсутствие колонки `description`, либо значения `NULL`.

Например:

```sql
INSERT INTO dim_eve_types (
    type_id,
    name,
    group_id,
    market_group_id,
    published,
    description
) VALUES (
    ...,
    ...,
    ...,
    ...,
    ...,
    NULL
)
```

или:

```sql
INSERT INTO dim_eve_types (
    type_id,
    name,
    group_id,
    market_group_id,
    published
) VALUES (
    ...,
    ...,
    ...,
    ...,
    ...
)
```

Ошибка:

```text
StringDataRightTruncation
value too long for type character varying(500)
```

должна исчезнуть.

# 6. Проверка после изменений

Выполнить:

```bash
python -m py_compile jita_loader.py
```

Должно пройти без ошибок.

Проверить поиском:

```bash
grep -n "region_json.get('description')" jita_loader.py
grep -n "type_json.get('description')" jita_loader.py
grep -n "stmt.excluded.description" jita_loader.py
```

Все три команды должны вернуть пусто.

Допустимый остаток:

```bash
grep -n "description" jita_loader.py
```

должен показывать только определения колонок в моделях, например:

```python
description = Column(String(500), nullable=True)
```

```python
description = Column(String(2000), nullable=True)
```

и, возможно:

```python
'description': None
```

---

# 7. Важный нюанс про старые данные

Если просто убрать `description` из `INSERT` и `ON CONFLICT`, то:

- новые строки будут без описания;
- старые строки могут остаться со старыми описаниями.

Если нужно именно полностью очистить уже накопленные описания, можно один раз выполнить:

```sql
UPDATE dim_eve_regions
SET description = NULL
WHERE description IS NOT NULL;

UPDATE dim_eve_types
SET description = NULL
WHERE description IS NOT NULL;
```

Это не меняет структуру таблиц, только чистит данные.

Но если нужно просто перестать сохранять описания — достаточно правок выше.

---

# 8. Короткий итог

Во всех местах, где в справочники пишутся данные из ESI:

```python
description = ...
```

убрать.

Вместо текста писать:

```python
'description': None
```

или вообще не передавать поле `description`.

В `ON CONFLICT DO UPDATE` убрать:

```python
'description': stmt.excluded.description
```

и заменить на:

```python
'description': None
```

Таблицы и модели не менять. Список регионов не менять.
